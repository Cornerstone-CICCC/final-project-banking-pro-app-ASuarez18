This assignment proved to be significantly more challenging than anticipated, given that I needed to do  substantial refactoring of the original codebase to make it testable within the scope of what was covered in class. The initial implementation relied heavily on asynchronous user input and file I/O operations, which it completely made unit testing extremely difficult without the advanced mocking techniques that weren't part of the syllabus. As I said, I had to perform a partial refactoring of most functions, converting them from async CLI-driven operations to pure functions that accept parameters directly and return modified data objects or values. This unexpected additional work transformed what should have been a testing exercise into a combined refactoring and testing challenge, so it was a little bit fun and frustrating at the same time.

Despite the frustration of dealing with these implementation obstacles i felt that the experience that I got from this activity was invaluable. Even though I've already have little experience in testing, getting to do all the process of identifying bugs through both black-box and white-box testing methodologies was a fulfilling experience, from finding critical flaws that would have caused serious issues in production, such as NaN balance corruption, money vanishing in transfers to accounts ending in '7' (which is funny because bugs like this happens, It happened to me), and the ability to create ghost accounts. Writing comprehensive test cases made me to think deeply about edge cases, input validation, and the importance of maintaining data integrity throughout all operations.

I now understand at a fundamental level why testing is non-negotiable in professional software development. The bugs I discovered from accepting invalid inputs that occasioned losing transaction records or full account balances, that in a real case scenario they would have created catastrophic failures in a real banking system. Although the assignment was frustrating at times, particularly when dealing with test isolation and refactoring, it demonstrated that the cost of writing tests upfront is minimal compared to the cost of debugging production failures or, worse, financial losses due to undetected bugs.
